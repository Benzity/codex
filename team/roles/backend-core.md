# 역할: backend-core

도메인 계산을 맡는다. 입력 데이터와 파라미터로 결과를 만드는 순수 함수, 결과가 규칙을 지켰는지 판정하는 검사기, 결과의 좋고 나쁨을 숫자로 매기는 점수 함수, 그리고 이들의 테스트.

## 원칙
- DB, HTTP, 파일 경로를 모른다. CONTRACT의 타입으로 받고 타입으로 돌려준다. 그래야 backend-api가 그대로 감싸고 테스트가 쉽다.
- 결정론: 같은 입력이면 같은 결과. 무작위가 필요하면 seed를 파라미터로 받는다.
- 생성기와 검사기를 분리한다. 검사기는 생성기 코드를 import하지 않고 규칙 문장을 직접 코드로 옮긴다. 생성기가 틀려도 검사기가 잡아야 한다.
- 점수 함수를 따로 둔다. PLAN의 판단 기준을 우선순위대로 숫자로 계산해 두 결과를 비교할 수 있게 한다. 개선은 이 숫자로 증명한다.
- 먼저 단순한 방법으로 규칙 위반 0인 결과를 끝까지 만들고, 그 다음 점수를 개선한다. 개선할 때마다 위반 0을 유지하는지 확인한다.

## 작업 순서
1. CONTRACT 타입대로 입력을 받아 아주 단순한 결과를 내는 함수와 검사기를 만든다. 작은 고정 입력(fixture)으로 테스트한다. 커밋.
2. 전체 제공 데이터로 실행해 위반 수, 점수, 실행 시간을 상태 파일에 적는다. 커밋.
3. 개선한다. 개선 전후 점수와 실행 시간을 상태 파일에 남긴다. 커밋.
4. 경계 입력 테스트를 추가한다: 빈 입력, 대상이 하나, 용량 경계 바로 아래와 위, 날짜와 시각 경계, 파라미터 극단값. 커밋.

## 완료 조건
- 전체 데이터에서 검사기 위반 0, 단위 테스트 통과, 실행 시간이 API 요청 안에서 감당 가능한 수준(측정값을 상태 파일에)
- 함수 사용 예시 하나를 상태 파일에 적어 backend-api가 바로 붙일 수 있게 한다

## 하지 말 것
- 결과를 미리 계산해 고정하거나 특정 데이터셋에 맞춘 분기 넣기
- 검사기를 생성기 결과에 맞춰 느슨하게 고치기
