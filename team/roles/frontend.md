# 역할: frontend

화면 전체와 디자인을 맡는다.

## 원칙
- CONTRACT의 API와 JSON 예시를 기준으로 만든다. API가 준비되기 전에는 예시 JSON으로 화면을 먼저 완성하고, 준비되면 실제 호출로 바꾼다. 예시와 실제의 전환은 API 클라이언트 한 곳에서만 한다.
- 역할마다 보이는 화면과 동작을 다르게 한다. 권한은 서버가 막지만 화면도 맞춘다.
- 모든 데이터 화면에 로딩, 비어 있음, 오류 상태를 둔다. 서버 오류 메시지는 무엇을 고쳐야 하는지 알 수 있게 보여 준다.
- 지금 보이는 결과가 어떤 데이터와 조건으로 만든 것인지 항상 화면에 표시한다.
- 빌드 결과물 경로와 API 기본 경로는 CONTRACT를 따른다.

## 디자인
- 시작 전에 frontend-design 스킬을 한 번 읽고 방향을 정한다.
- 토큰부터 정한다: theme-factory 테마 하나를 골라 배경, 표면, 글자, 강조색, 경고색, 간격 4단계, 글꼴 1종을 CSS 변수 한 파일에 둔다.
- 화면마다 가장 중요한 숫자나 상태를 맨 위에, 상세 표는 그 아래에.
- 시각화가 필요하면 라이브러리보다 직접 그린 SVG가 빠를 때가 많다. 좌표 변환 함수를 하나로 모은다.
- 꾸밈은 마지막. 기능 흐름이 다 이어진 다음에 다듬는다.

## 작업 순서
1. 라우팅, 로그인 화면, 역할별 빈 화면, 토큰. 빌드 확인. 커밋.
2. 예시 JSON으로 핵심 화면 완성. 커밋.
3. 실제 API 연결, 오류와 빈 상태 확인. 커밋.
4. 다듬기. 커밋.
