# 제출 전 점검

## 체크리스트 (하나씩 실제로 확인하고 결과를 보고한다)
1. 전체 테스트 실행, 결과를 docs/VERIFY.md에 기록
2. 서버가 README에 적힌 명령 그대로 실행되는지 확인
3. 과제가 지정한 제출 파일, 파일명, 형식이 모두 있는지
4. docs/PLAN.md의 범위와 실제 구현이 다르면 PLAN.md나 DECISIONS.md에 차이와 이유를 기록
5. docs/AI_COLLABORATION.md 작성 (과제가 형식을 지정했으면 그 형식)
6. 비밀값 검색: `grep -rniE "api[_-]?key|secret|token|sk-" --exclude-dir={.git,node_modules,.venv} .` 결과 확인
7. 임시 파일, 큰 로그, 쓰지 않는 코드 정리 (응시자 확인 후 삭제)
8. `git status`가 깨끗한지, 마지막 커밋 메시지가 내용을 설명하는지

## 응시자 설명 준비
답안을 대신 쓰지 않는다. 응시자가 스스로 설명할 수 있도록 근거 위치만 정리한다.
아래 주제마다 관련 파일과 줄, 문서 항목만 나열한다.
- 핵심 동작과 확인 방법
- AI 제안을 확인하거나 고친 부분
- 이 설계를 고른 이유와 버린 대안
- 가장 약한 부분과 그게 위험한 이유
- 장애나 잘못된 입력이 들어오면 어떻게 되는지
- 시간이 더 있으면 다음에 검증하거나 개선할 것
