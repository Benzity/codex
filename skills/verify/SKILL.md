# 검증

## 1. 요구사항과 증거 연결
docs/VERIFY.md의 "요구사항별 증거" 표에서 PLAN.md의 요구사항과 성공 기준마다 확인 방법을 정한다.
증거가 없는 요구사항은 "미확인"으로 남겨 두고 응시자에게 알린다.

## 2. 확인 방법 (해당되는 것을 모두)
- 자동 테스트: 예) `python -m pytest -q`. 결과 요약(통과 수, 실패 수)을 기록한다.
- API: curl로 정상 요청 1개, 잘못된 요청 1개 이상. 상태 코드와 응답 핵심을 기록한다.
- 화면: 응시자가 브라우저 미리보기로 확인할 시나리오를 단계별로 적어 준다. 확인은 응시자가 한다.
- 예외: 빈 입력, 잘못된 형식, 경계값, 중복, 큰 입력.
- 데이터 결과: 처음과 다른 방법으로 한 번 더 계산해 같은지 본다 (예: pandas 집계 vs 순수 파이썬 반복).

## 3. 기록 형식
| 시각 | 무엇을 | 명령 | 결과 |
결과에는 실제 출력의 핵심만 쓴다. 실행하지 않았으면 쓰지 않는다.

## 4. 실패했을 때
원인 가설 → 최소 재현 → 수정 → 같은 명령으로 재실행. 이 과정도 한 줄로 남긴다.
AI(너)의 이전 제안이 원인이었으면 DECISIONS.md "AI 제안 검토" 표에도 남긴다.
