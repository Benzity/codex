# 계획 수립

## 원칙
- 먼저 끝까지 동작하는 최소 버전(MVP)을 만든다. 남은 시간에 다듬는다.
- 작업 단위는 30분 이하, 각각 완료 조건(어떤 테스트나 확인이 통과하면 끝인지)을 붙인다.
- 담당자에게 확인하지 않은 가정은 가정이라고 표시한다.

## docs/PLAN.md 채우는 순서
1. 문제 정의: 누구의 어떤 문제를 무엇으로 푸는지 한 문장
2. 성공 기준: 측정 가능한 것으로 3개 이내
3. 범위: 이번에 할 것 / 하지 않을 것 (하지 않는 이유 포함)
4. 가정: 각 가정 옆에 "담당자 확인됨" 또는 "미확인"
5. 설계 개요: 입력 → 처리 → 출력, 주요 파일 구조
6. 작업 단위: 순서, 예상 시간, 완료 조건
7. 리스크: 무엇이 틀릴 수 있고, 어떻게 일찍 알아챌지

## 시간 예산 (작업 180분 기준)
- 0~20분: 과제 파악, 인터뷰, 계획
- 20~110분: MVP 구현 루프
- 110~150분: 통합 검증, 예외 처리, 담당자 중간 확인
- 150~170분: 문서 정리, 제출 점검
- 170분 전: 제출

계획을 바꾸면 PLAN.md를 고치고 DECISIONS.md에 이유를 남긴다.
